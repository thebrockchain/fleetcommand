# IBM Bob 2.0 Hackathon plan (third target)

Event: online, 48 hour build window Sep 25 to 27, 2026. $10,000 pool.
Different rules of engagement: the build must happen INSIDE the window, so
nothing can be pre-submitted. This file is the battle plan, not paste copy.

## The plan

1. Brock registers before the window (ToS is human only). Confirm the
   event's rules on pre-existing code the day registration opens: most 48
   hour events allow building ON an existing public concept but require the
   window's work to be new.
2. In-window build: a NEW capability on Fleet Command sized to 48 hours,
   for example the approval queue (multiple staged missions, an audit trail
   of every human decision) or a second mission type. New repo or clearly
   scoped commits so the window's work is provable in git history.
3. Reuse the mission demo pattern and the honest replay/live design; both
   are strong differentiators against 48 hour hack slop.
4. If IBM's stack (watsonx, Bob) is required by the rules, decide fit at
   registration time; do not force our stack into a rules violation. If it
   does not fit honestly, we skip this one and lose nothing.

## Why we keep it on the list

Cash pool per hour of work is strong, the build muscle already exists, and
a second win compounds the credibility of the first two entries.
